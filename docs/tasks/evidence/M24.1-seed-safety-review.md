## Confirmed blockers

1. `resolveSeedOwnedRecordIds` collects each child's `id`, but `cleanupSeedOwnedRecords` compares those values with foreign-key columns. Examples: room-slot assignment IDs compared with `room_slot_id`, payment IDs with `reservation_id`, and membership IDs with `group_id`. Cleanup can leave records behind or fail later on dependencies. Correcting only the missing membership `org_id` filter does not fix this.
2. Ownership discovery adopts all departures of registered packages and all reservations of registered customers. The subsequent foreign-dependent checks exclude this expanded set, so they cannot detect user-created departures/reservations already adopted into it. Parent association alone does not prove seed ownership. Reset must refuse unregistered business records rather than cascade-delete them.
3. The new helper test imported an executable seed script. Added a CommonJS entry-point guard and a mocked database assertion so importing the module does not run the seed.

Additional finding: `goldenSeedRecordIds` is never populated, so its final registered-record count is always zero. Database-generated UUIDs also mean deterministic fixture content is not deterministic record identity; the active specification must not claim stable IDs without evidence.
